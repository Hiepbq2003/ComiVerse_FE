1.2 System Scope Summary

Comiverse— An online manga reader and collaborative translation platform for manga enthusiasts, creators, and translation groups. 

Comiverse is a web-based manga platform that integrates an advanced collaborative translation workspace and a personalized content discovery system. It centralizes the entire manga lifecycle—from raw image uploading by Authors, real-time chapter translation and approval workflow by Translator Teams (Translators &amp; Leaders), content moderation by Moderators, to an interactive reading experience for Readers featuring a Cosine Similarity-based recommendation engine. 




1.3 Actors:

Actor

Role in the system

Guest 

Unauthenticated visitor; can browse the comic catalog, search for titles, read free chapters, and register an account. 

Reader 

Authenticated user; inherits all Guest permissions, can save comics to a library, bookmark reading progress, rate/comment, and unlock premium chapters. 

Translator 

Scanlator/Translator; responsible for translating, editing, and uploading new chapters for assigned or self-translated comic series. 

Project Leader

Translation team manager; inherits all Translator permissions, holds authority to approve or reject translation drafts submitted by Translators, and manages team membership (accepting or removing members from the translation group).

Author 

Content creator/Artist; can publish and manage original work, upload chapters, and interact directly with readers on their comic pages. 

Moderator 

Content reviewer; monitors user comments, reviews chapters uploaded by Translators/Authors, and handles user reports to maintain community guidelines. 

Admin 

Super administrator; holds full system control, manages user accounts and role assignments, oversees monetization/transactions, and configures global platform settings.

5.2 JOB-01 — Persist Buffered Reading Activity and View Counters 

Attribute

Value

FT-ID ref

FT-01

Trigger

Scheduled — every 5 minutes

UC-ID ref

UC-01

Purpose

Flush temporarily buffered comic views, chapter views, and user reading histories from Redis into the PostgreSQL persistent database.




Processing steps:

Sync Comic View Statistics:

Fetch all pending comic view counter keys from Redis.

Atomically decrement/reset the counter offset in Redis.

Update total daily view log (comic_daily_views) and overall view count in comics table in PostgreSQL.

Evict cached comic detail objects from Redis cache.

Sync Chapter View Statistics:

Fetch all pending chapter view counter keys from Redis.

Decrement Redis counter offsets and increment view counts in PostgreSQL chapters table.

Sync User Reading History:

Read queued reading history tracking payloads from Redis.

Upsert user chapter reading history entries in PostgreSQL reading_histories table.




Failure behavior:

Scenario

System behavior

Database failure during view sync

Deducted counts can be retried or logged. Unsaved reading history items remain in the Redis queue for the next 5-minute cycle.

Redis connection unavailable

Skip execution. Next run will process accumulated counters once Redis connectivity is restored.

Cache eviction fails for a comic

Log error details; database update remains committed and valid.

Concurrent history deletion by user

If a user deletes history while sync is queued, explicit deletion logic purges both database entries and pending Redis queue items matching that user and comic.




5.3 JOB-02 — Clean Up Expired Reading History Logs 

Attribute

Value

FT-ID ref

FT-03, FT-08

Trigger

Scheduled — daily at 12:00 AM Midnight 

UC-ID ref

UC-18, UC-19, UC-43 

Purpose

Purge obsolete user reading history logs older than the retention threshold to prevent database bloat and optimize query performance.




Processing steps:

Query reading_histories table for records created before the retention threshold date.

Delete expired history records in chunked batch operations to minimize lock contention.

Invalidate associated reading history Redis cache keys for impacted users.




Failure behavior:

Scenario

System behavior

Database query timeout during batch purge

Abort current batch transaction, log warning, and attempt remaining items in the next scheduled midnight execution.

Redis cache clearance error

Proceed with database record deletion; log cache eviction failure for manual review if persistent.





5.4 JOB-03 — Compute Comic View Leaderboards 

Attribute

Value

FT-ID ref

FT-03, FT-04, FT-14

Trigger

Scheduled — every 15 minutes 

UC-ID ref

UC-18, UC-19, UC-43 

Purpose

Aggregate comic daily view statistics across daily, weekly, and monthly timeframes, and cache the top-ranked published comics in Redis for fast leaderboard retrieval. 




Processing steps:

Compute Daily Rankings:

5.7 JOB-06 — Recalculate User Preference Vectors 

Attribute

Value

FT-ID ref

FT-10, FT-11, FT-12

Trigger

Scheduled — hourly at minute 30 

UC-ID ref

UC-06, UC-07, UC-10, UC-20 

Purpose

Periodically recompute user preference vectors by averaging 768-dimensional embedding vectors of comics that each user liked, saved, or read (combining PostgreSQL and un-synced Redis queues). 




Processing steps:

Query database for active user IDs flagged with pending vector updates .

If no active users have new interactions, finish execution immediately.

For each identified user:

Collect all interacted comic IDs by aggregating database records (likes, saves, reading history) and pending reading entries in the Redis sync queue.

If the user has zero interacted comics, set user_vector to null, update vector_updated_at timestamp, and proceed to the next user.

Fetch valid 768-dimensional summary_vector arrays for all interacted comics.

Compute the element-wise average vector across all valid interacted comic vectors.

Save the calculated preference vector array into user_vector and update vector_updated_at on the user record.




Failure behavior:

Scenario

System behavior

Interacted comics lack embeddings 

If none of the user's interacted comics have embeddings yet, skip updating user_vector and keep existing preference data. 

Redis connection error 

Catch exceptions, fallback to using database interaction records alone, and continue computing the vector. 

User preference vector calculation fails 

Log exception details for that specific user ID and continue processing remaining users.
